סרבר א': endpoints לקריאה

השלב השני בשרת: ה-GET של המסך, לפי החוזה, עם בדיקת הרשאה, סינון ובדיקות.

בעמוד הזה: לפני שמתחילות · מה בונים · ה-route · הרשאות · בדיקה · מתי זה גמור · טעויות נפוצות

לפני שמתחילות

  • ה-PR של הסכמות וה-seed של המסך מוזג ל-dev, ו-npm run seed ממלא את הנתונים.
  • השרת רץ על המחשב (ההתקנה), ואת פותחת את החוזה כ-Swagger (איך פותחים).
  • קראת את routes.ts במודול ההדרכה school-server/src/modules/announcements/. זו התבנית ש-new:module יוצר.

שלב 1: מה את בונה

בעמוד המסך באפיון, בסעיף "שרת ונתונים", בטבלה "ה-endpoints בחוזה": בונות את השורות שהשלב שלהן הוא "סרבר א'" (כל ה-GET). בטבלה כתוב לכל endpoint הנתיב, הפרמטרים, וסכמת התגובה בחוזה.

ב-endpoint שמסומן טרם הוגדרה (endpoint שמרכז נתונים, כמו דשבורד או סיכום): כותבות את מבנה התגובה ב-openapi.yaml, בשני העותקים (שרת וקליינט), באותו PR של ה-route. ראשת הצוות רואה אותו בקוד ריוויו.

שלב 2: ה-route ב-routes.ts

// GET /api/foos?page=1&size=25
router.get(
  '/foos',
  authorize('S06', 'read'),                                  // 1
  asyncHandler(async (req, res) => {
    const { page, size, skip } = parsePagination(req.query); // 2
    const filter = { institutionId: req.user!.institutionId }; // 3
    const [items, total] = await Promise.all([
      Foo.find(filter).sort({ createdAt: -1 }).skip(skip).limit(size).lean(),
      Foo.countDocuments(filter),
    ]);
    const mapped = items.map((f) => ({                     // 4
      id: String(f._id),
      name: f.name,
      status: f.status,
    }));
    res.json(toPage(mapped, total, page, size));
  }),
);
  1. 1. בדיקת הרשאה, עם מזהה המסך. השורה המוכנה כתובה בעמוד המסך.
  2. 2. עימוד, כשהתגובה בחוזה היא ...Page. כשהיא ...List מחזירות { items } בלי עימוד.
  3. 3. כל שאילתה מסוננת לפי המוסד של המשתמש.
  4. 4. ממפות כל רשומה לצורה שבחוזה: id כמחרוזת, אותם שמות שדות, ובלי שדות פנימיים כמו institutionId או __v. שדה ריק נשלח כ-null.

אם האוסף בליבה: מייבאות אותו מ-../../models. שורת ה-import המוכנה כתובה בעמוד המסך.

שלב 3: הרשאות

בסרבר א' צריך לדעת שני דברים בלבד. את שאר ההרשאות (כתיבה, צפייה בלבד, מי מורשה לערוך) לומדים בסרבר ב'.

1. השורה authorize

authorize('<מסך>', 'read') בודקת את מטריצת ההרשאות לבד: משתמש בלי טוקן מקבל 401, ומשתמש בלי גישה למסך מקבל 403. לא צריך לכתוב את הבדיקה בעצמך.

2. "מוגבלת לשלו" (scoped)

בטבלת ההרשאות בעמוד המסך מופיעה לכל תפקיד רמת הגישה שלו. כשכתוב "מוגבלת לשלו", ה-GET חייב לסנן: מורה רואה רק את הכיתות שלה, והורה רואה רק את הילדים שלו. בלי הסינון הזה, מורה תראה את התלמידים של כל בית הספר.

import { getScopedClassIds } from '../../services/scope';

if (req.accessLevel === 'scoped') {
  filter.classId = { $in: await getScopedClassIds(req.user!.id) };
}

להורה: הילדים שלו הם התלמידים שבשדה guardians שלהם יש userId שלו (Student.guardians[].userId).

שלב 4: בדיקה

  • בדיקה אוטומטית לכל endpoint: בלי טוקן מקבלים 401, ועם טוקן התגובה במבנה של החוזה. התבנית ב-routes.test.ts שנוצר.
  • בדיקה ידנית: npm run dev, ואז curl עם טוקן. הפקודות המוכנות בקובץ school-server/docs/new-module.md, בסעיף "איך בודקים endpoint ידנית".
  • ואז: npm run verify ו-PR קטן ל-dev.

מתי זה גמור

  • ה-endpoints זהים לחוזה: נתיב, פרמטרים ומבנה התגובה
  • עימוד, מיון וסינון לפי החוזה
  • authorize בכל route, סינון לפי מוסד, וסינון "מוגבלת לשלו" כשהוא נדרש
  • בדיקה לכל endpoint, ו-npm run verify ירוק

את הכתיבה (POST, PUT ו-DELETE), הולידציה ב-schema.ts וההרשאות המלאות בונים בסרבר ב'.
