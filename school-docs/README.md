# school-docs

מסמכי הפרויקט של מערכת הניהול הפדגוגית: אפיון, עיצוב, תרשימי זרימה וחלוקת צוותות. כולם דפי HTML סטטיים, ואין צורך בהתקנה או בשרת.

## איך פותחים

פותחים את `index.html` בדפדפן. הוא מקשר לכל המסמכים.

## מבנה

```
index.html       דף כניסה עם קישורים לכל המסמכים
guides/          מדריכי עבודה לבנות (למשל ספרינט 2)
spec/            אתר האפיון: אינדקס, תוכנית עבודה, משימות, עקרונות, ועמוד לכל מסך (screens/)
design-kit/      מדריך העיצוב, טוקנים, קובץ Tailwind, ורשימות רכיבים ופריימים ל-Figma
flows/           תרשים זרימת המסכים ותרשימי התהליכים (HTML, PNG ומקור Mermaid)
teams/           חלוקה לצוותות, תפקידים וניווט, ומטריצת הרשאות
```

תיקיית `spec` חייבת להישאר שלמה, כי הדפים בה מקשרים זה לזה בנתיבים יחסיים.

## איך מעדכנים

הדפים נוצרו בהתחלה בבת אחת מתוך האפיון, ומאז הם המקור עצמו: אין כלי שיוצר אותם מחדש. כשמשהו משתנה (מסך, תלות, החלטה), עורכים ישירות את קבצי ה-HTML שהשתנו ופותחים PR ל-`main`.

כדאי לשים לב לשני דברים:

- **אותו מידע מופיע בכמה מקומות.** למשל, שלבי העבודה של מסך מופיעים בעמוד המסך (`spec/screens/SCR-*.html`), בלוח המפתחות (`spec/tasks.html`) וגם ב-`SPEC.md` של המסך בריפו של הקליינט. שינוי באחד מהם מעדכנים בכולם באותו PR.
- **מדריכי העבודה לבנות נמצאים כאן**, בתיקייה `guides/`, ובכל עמוד מסך יש סעיף "שרת ונתונים". שינוי בכלל בקוד (מודל, הרשאות, חוזה) מעדכנים גם כאן.

## אירוח (אופציונלי)

- **GitHub Pages:** מציג את הדפים בכתובת אינטרנט. לריפו פרטי הוא זמין רק בתוכניות משלמות של GitHub. הקובץ `.nojekyll` כבר קיים.
- **AWS:** אתר סטטי ב-S3 עם CloudFront, או nginx על מופע קיים, ומומלץ להגן עליו בסיסמה.
