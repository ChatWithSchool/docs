מה מוכן לפני ספרינט 1 (הרכזת וראשי הצוותות)

  • Repository ב-GitHub עם ענפים dev ו-stage, הגנה על ענפים, תבנית PR ובדיקות אוטומטיות
  • סביבות dev ו-stage ב-AWS (EC2, ו-S3 לקבצים) עם פריסה
  • שלד קליינט: React, TypeScript, Redux ו-Tailwind עם הטוקנים של מערכת העיצוב, ניתוב, לקוח API ומסגרת X01
  • שלד סרבר: Node, TypeScript ו-Mongoose מול MongoDB, עם אימות JWT ובדיקת הרשאות לפי מטריצת הרשאות
  • מצבי מערכת משותפים (X02) והתחברות (A01)
  • אוספי ליבה (institutions, academic_years, users, roles, role_permissions, staff_profiles, classes, students, subjects) וקובץ seed בסיסי שכל הצוות משתמש בו
  • 10 אוספים משותפים (grades, grade_feedback, assessments, attendance_records, attendance_alerts, lessons, teaching_assignments, events, rooms, invites): מודל, seed וסכמות מפורטות בחוזה. אלה האוספים שיותר מצמד אחד קורא מהם, ולכן הם מוכנים מראש ואף מסך לא מחכה לצמד אחר (ראו SHARED-COLLECTIONS-PLAN.md)
  • חוזה OpenAPI מלא לכל ה-endpoints של 46 המסכים, ושרת Mock שנוצר ממנו
  • קובץ Figma עם יסודות (Foundations), רכיבים ופריימים לכל מסך (ראו ערכת העיצוב)
  • ערוצי Slack: ערוץ צוות לכל צמד סמוך, וערוץ ראשי צוותות
  • שלושה בורדי Jira (מערכת אחת לכל צוות), כל אחד מיובא עם המסכים והמפתחות של הצוות

זרימת העבודה של כל תת-משימה

  1. סוף יום רביעי: מקבלות שתי משימות (שני המסכים של השלב) ומבינות אותן: תיאור ב-Jira, עמוד המסך באפיון והפריים ב-Figma
  2. מושכות את הריפו ופותחות ענף feature/SCR-XXX-שלב מתוך dev
  3. עובדות עד יום שלישי: פיתוח ובדיקה מקומית, ושאלות ב-Slack אחרי ניסיון עצמאי של 20 דקות
  4. יום שלישי: פותחות PR קטן ל-dev, חברה עושה קוד ריוויו, ואחרי אישור ממזגות ל-dev
  5. יום שלישי: בדיקות ידניות ב-dev לפי קריטריוני הקבלה
  6. יום רביעי: מיזוג מ-dev ל-stage
  7. יום רביעי: קבלת משימות חדשות והבנה שלהן, ומתחילות שוב

המחזור השבועי נקבע עם ראש הצוות המלווה: ספרינט נמשך מסוף יום רביעי עד יום רביעי הבא, ושינויים אפשריים לפי הצורך. התשתית: GitHub, Jira, Slack, Figma ו-AWS (סביבות dev ו-stage).
