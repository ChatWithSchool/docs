רכיבים משותפים

המסך נבנה רק מהרכיבים המשותפים שב-src/components/ui. לכל רכיב יש הסבר, props ודוגמת קוד במדריך הרכיבים המשותפים. מה שלא ברשימה ולא במדריך: שואלות את ראשת הצוות לפני שבונות.

PageHeader ◇ Tabs ◇ Table TextField ◇ DatePicker ◇ Badge ◇ Toast Button ◇

◇ = מחובר בפריים ב-Figma: לוחצות עליו ורואות את שורת הקוד בחלונית הימנית. בלי ◇ = עדיין מצויר ב-Figma: רואות אותו ב-Storybook (npm run storybook), עם קישור במדריך.

  • המסגרת (סרגל עליון, תפריט צד ולשוניות המודול) מגיעה מ-AppShell. לא בונים אותה במסך.
  • מצבי טעינה, ריק ושגיאה: לפי הטבלה במדריך (Table, EmptyState, StateViews).

פעולות ותגובות

  • 'נתק מכל המכשירים' מנתק הכול מלבד הנוכחי, אחרי אישור.
  • הפעלת אימות דו-שלבי דורשת הזנת קוד תקין לפני שהיא נשמרת.
  • שינוי סיסמה מנתק את שאר המכשירים.

כללים ותנאים

  • אימות דו-שלבי חובה להנהלה ואופציונלי לאחרים.
  • מדיניות סיסמה מוגדרת למוסד; פקיעת סשן אחרי חוסר פעילות.
  • יומן הפעילות מציג רק פעולות של המשתמש עצמו; המנהל רואה יומן מוסדי ב-A04.

המודול בשרת

תיקייה מוצעת: src/modules/sessions, שנוצרת עם npm run new:module -- session --screen A06.

שם הבדיקה ב-authorize: authorize('A06', 'read') ל-GET, ו-'write' לכתיבה.

sessions בונות: המודל Session

אלה השדות של המודל. הם נגזרו מהאפיון של המסך: אזור 'מכשירים פעילים' (מכשיר ודפדפן, מיקום משוער, כניסה אחרונה, ניתוק). ה-API מחזיר אותם לפי הסכמה Session בחוזה (בלי institutionId). חסר שדה? כותבות לראשת הצוות.

לראות את החוזה המלא כ-Swagger: איך פותחים.

"טרם הוגדרה": זה endpoint שמרכז נתונים, ובחוזה כתוב עדיין רק type: object. בעלת המסך כותבת את מבנה התגובה ב-openapi.yaml באותו PR של ה-route, וראשת הצוות רואה אותו בקוד ריוויו. אין שלב אישור נפרד.
