מטרת המסך

התצוגה השבועית של מערכת השעות במבטים שונים: לפי כיתה, לפי מורה, לפי חדר. הורה ומחנך רואים קריאה בלבד.

מה נבנה בגרסה 1

נכלל (v1-lite)
רשת שבועית לפי כיתה ולפי מורה; הדפסה דרך הדפדפן.
נדחה
מבט לפי חדר; ייצוא PDF.

שאר המפרט בעמוד הוא תיאור המסך המלא. כשיש סתירה, ההיקף של v1-lite הוא שקובע מה נבנה עכשיו.

רכיבים משותפים

המסך נבנה רק מהרכיבים המשותפים שב-src/components/ui. לכל רכיב יש הסבר, props ודוגמת קוד במדריך הרכיבים המשותפים. מה שלא ברשימה ולא במדריך: שואלות את ראשת הצוות לפני שבונות.

PageHeader ◇ Select ◇ TextField ◇ Checkbox ◇ Badge ◇ LessonBlock IconButton ◇ Button ◇

◇ = מחובר בפריים ב-Figma: לוחצות עליו ורואות את שורת הקוד בחלונית הימנית. בלי ◇ = עדיין מצויר ב-Figma: רואות אותו ב-Storybook (npm run storybook), עם קישור במדריך.

  • המסגרת (סרגל עליון, תפריט צד ולשוניות המודול) מגיעה מ-AppShell. לא בונים אותה במסך.
  • מצבי טעינה, ריק ושגיאה: לפי הטבלה במדריך (Table, EmptyState, StateViews).
  • רשת מערכת השעות נבנית במסך, וכל שיעור בתוכה הוא LessonBlock.

פעולות ותגובות

  • מורה נפתח אצלו כברירת מחדל המבט האישי; הורה רואה את כיתת ילדו.
  • 'PDF' מפיק קובץ ברור להדפסה על A4 לרוחב.
  • במובייל התצוגה עוברת לרשימה יומית.

כללים ותנאים

  • במבט קריאה בלבד אין כפתורי עריכה.
  • שיעור עם ממלא מקום מציג את שם החלופי.
  • אירוע יומן (I07) מסמן יום חופשה ברשת.

המודול בשרת

תיקייה מוצעת: src/modules/schedules, שנוצרת עם npm run new:module -- schedule --screen T01.

אין למסך אוסף פרטי, ולכן מוחקות את model.ts שנוצר ומייבאות מהליבה.

שם הבדיקה ב-authorize: authorize('T01', 'read') ל-GET, ו-'write' לכתיבה.

לראות את החוזה המלא כ-Swagger: איך פותחים.

"טרם הוגדרה": זה endpoint שמרכז נתונים, ובחוזה כתוב עדיין רק type: object. בעלת המסך כותבת את מבנה התגובה ב-openapi.yaml באותו PR של ה-route, וראשת הצוות רואה אותו בקוד ריוויו. אין שלב אישור נפרד.
